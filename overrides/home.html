The problem

The script is easy.
Landing it is the work.

Pinning an action, bumping a Go version or adding a config file takes minutes in one repo. Across an organization it means cloning, branching, pushing, opening PRs, and then watching which ones fail checks, wait for review or never merge. gh fleet runs that loop for you and keeps the ledger.

  • {% include ".icons/material/check-decagram-outline.svg" %}Re-running apply updates open PRs instead of duplicating them
  • {% include ".icons/material/check-decagram-outline.svg" %}One repo failing never stops the others, and retry picks up only those
  • {% include ".icons/material/check-decagram-outline.svg" %}GitHub is the source of truth, so status works with no local state

Core concepts

Describe it once.
Preview, apply, follow.

A campaign is one YAML file: which repos, what to run in each, how to open the PR. Everything else is three verbs.

Campaign

A file you commit and review

Targets, a script and a PR template. The name derives the branch and the hidden PR marker.

name: pin-actions
targets:
  orgs: [acme]
  include:
    files: [.github/workflows]
change:
  run: ./scripts/pin.sh
pr:
  title: "ci: pin GitHub Actions"

Plan

Before anything is pushed

Runs the script in a fresh clone of each repo and prints the diff it would send. Repos with no diff are noops.

$ gh fleet plan --repo acme/api
── acme/api
-  - uses: actions/checkout@v4
+  - uses: actions/checkout@08eb… # v4

1 changed · 1 skipped

Track

Until the last PR merges

Status reads every PR back from GitHub: state, checks and review decision, one batched query per 50 repos.

$ gh fleet status
3 pr open · 1 merged
1 noop · 1 skipped

Quick start

From install to a PR
in five commands.

You need the GitHub CLI signed in with gh auth login and git on your PATH. gh fleet uses gh's authentication and never asks for a token.

{% include ".icons/material/book-open-page-variant-outline.svg" %} Full getting-started guide

  1. Install

    $ {{ install }}

  2. Scaffold a campaign

    Writes fleet.yaml with every option shown and commented.

    $ gh fleet init pin-actions --org acme

  3. See what it will touch

    Lists each repo and the filter that matched it.

    $ gh fleet targets

  4. Preview one repo

    $ gh fleet plan --repo acme/api

  5. Open the PRs, then follow them

    $ gh fleet apply
$ gh fleet status
